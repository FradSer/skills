## Routing Rules

1. **Load the product context first.** Read
   [product-marketing](product-marketing/product-marketing.md) before any other
   workflow, once per session. It records the product, audience, positioning and
   voice that every other workflow builds on.
2. **Match the request to one row** of the index above, using the Use When
   condition. When two rows are close, take the one that owns the deliverable the
   user asked for.
3. **Read that workflow document** and follow its own reference routing before
   you write, draft, audit, or plan anything.
4. **Compose workflows for multi-domain work.** Read each one in task order and
   keep each document's own output contract. Never restate or override a routed
   workflow's rules from here.
5. **Resolve references inside a workflow.** A bare `SKILL.md` mention in a
   workflow's text means its own `<domain>/<domain>.md`. A sibling named in prose
   or backticks, for example `cro`, means `cro/cro.md`, and a path such as
   `references/foo.md` belongs to the workflow that names it.
6. **Name the gap instead of inventing coverage.** If no row covers the request,
   say which part is uncovered rather than answering from this index.

## Upstream and maintenance

The routed documents mirror
[coreyhaines31/marketingskills](https://github.com/coreyhaines31/marketingskills)
(MIT, see [coreyhaines31-LICENSE.txt](coreyhaines31-LICENSE.txt)). [README.md](README.md)
documents the layout and installation; [SYNC.md](SYNC.md) records the synced
revision and the transforms applied; [routes.yml](routes.yml) is the generated
route manifest behind the index table.

```bash
bash scripts/sync-marketing.sh --check   # read-only drift check against upstream
bash scripts/sync-marketing.sh           # rebuild the routed documents and index
```

`SKILL.md`, `README.md`, `SYNC.md`, `agents/` and `scripts/` are locally owned
and survive a sync. Every other file is derived; do not edit derived files
directly.
