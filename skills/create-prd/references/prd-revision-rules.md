# PRD 修订：业务准确优先于补齐形式

新建时用本文约束补写内容；核查、简化、修复已有 PRD 或策略表时，先读本文。

## 1. 区分需求、建议与未知

先按来源分类，不必把分类表全部塞进正文：

| 类型 | 依据 | 处理 |
|---|---|---|
| 确认事实 | 用户明确决定、当前有效需求或已核验资料 | 保留语义，标明冲突来源 |
| 建议方案 | 助手提出的排序、默认值、时长、阈值或新增流程 | 明示为建议，确认后才写成执行规则 |
| 待决策 | 来源缺失、互相冲突或依赖未验证 | 记录影响与所需证据；负责人和期限未知时不编造 |

“fix all”“修复所有问题”授权修复，不等于批准任意新增业务规则。明确错字、失效引用可直接修；影响触发、动作、优先级、退出时间的决定需要来源或确认。用户明确要求推荐方案时可给出方案，但不要宣称已批准或已实现。

不要为满足“可量化”而编造留存时长、重提醒间隔、性能数字或调研比例。未知的供应商能力和设备容量是待验证依赖，不是可由写作者拍板的产品规则。

## 2. 先简化概念，再选择表达

- 直接回答：哪个业务、何时触发、用户看到什么、何时退出。
- 并列业务、优先级、按钮与状态规则优先用表格；正文只补少量公共规则。
- 用户指定表格、文字或 Mermaid 时按指定格式交付。图只用于真实分支或时序，不把原长段落搬进图节点；“还是复杂”意味着减少概念与重复，而非换个容器。
- 区分交付优先级（P0/P1）与运行时展示顺序，不能自动互相推导。
- “一次只展示一张”只定义同时展示数量，不自动意味着禁止轮播或立即抢占；轮播、抢占、同级顺序各需明确依据。
- 不把状态机、持久化字段、幂等协议或任务拆分混进业务概览。确有实现需要时放独立技术说明。
- 改原章节并同步直接受影响的引用，不在文末反复追加“以本章为准”的覆盖规则。

## 3. 条件表达必须保持业务语义

策略表使用一行一个条件，以 `&&` 表示同时成立、`||` 表示任一成立；混用时用括号声明组合。不要将条件改成长句，也不要只写“按第8行判断”。行号可以用于定位修改，不能替代业务规则。

```text
用户在出发机场附近
&& 当前时间 >= 预计起飞时间 - 360分钟
&& 当前时间 <= 预计起飞时间
&& 本次提醒尚未发送
```

以上只是表达形式示例，不是所有出行业务的默认规则。

- 格式调整不改变 `>=` / `>`、`<=` / `<`、时间锚点、与或关系、默认值、通知动作或生命周期。
- 条件明显可疑时提出冲突和反例，不能凭“看起来应如此”反转比较符号。
- 每个事件按各自条件判断。静默推荐的窗口不能无依据地推广为延误、取消或登机口变化等独立事件的共同门槛。
- 通知去重只控制是否再次发送；推荐资格、实际展示和用户关注是不同判断，不能相互替代。
- 时间规则写明起算点、边界和结束条件；两条已确认规则冲突时列为待决策，而非自行发明一个时长解决。

修订前后用**同一输入**对照结果：窗口外发生独立事件、刚好处于时间边界、通知已经发过、同级多候选。若只是改写格式，输出行为必须一致；若需要改变行为，记录依据或待确认决定。

## 4. 已有文档与策略表的修改纪律

1. 读取最新内容、版本、真实行列或块标识，保护用户在其他会话的新改动。用户只要求检查时不写入。
2. 修改前记录目标位置、原值、新值、原因；用户要求“记录后还原”时保存可恢复基线及变更清单，并说明记录位置。区分恢复表达形式与回滚历史业务，不自动整表回滚。
3. 确认修改范围。引用资料可只读；同步其他文档或表格前说明范围并确认授权，不把链接视作任意改写许可。
4. 写入前再次核对目标版本或原值；出现并发修改则停止旧补丁、重读并重新确定差异，不覆盖新内容。仅使用当前工具实际支持的版本保护能力，不臆造参数。
5. 使用当前 Lark 技能及 CLI 帮助，不复制过期命令。局部写入、保留非目标的原有格式、图片与其他资源；单元格只改值时不重建整表。
6. 回读核对目标值、表格或图的实际存在、引用可用性及无关内容不变。删除错误规则时检查正文、表格、图和验收例，防止只删解释却保留限制。
7. 报告实际改动与验证边界。没有独立审查工具就说明未完成独立审查；请求成功不代表内容或视觉已验收。

## 5. 小型回归评审

用以下离线提示检查修订行为，不写真实远端资源：

| 输入 | 应有结果 | 不应出现 |
|---|---|---|
| “延误就通知并推荐；普通行程只在出发前窗口静默推荐。fix all。” | 保留两条独立规则，缺失结束条件列为待决策 | 给延误强加普通窗口、凭空加24小时 |
| “太复杂，使用表格，直接给业务逻辑。” | 业务、触发、展示、退出的简短表格 | 把长状态机换成大图或再追加覆盖章节 |
| “先记录修改，再恢复逐行 && 的形式。” | 先记录最新基线；保留逻辑运算符、比较符号、现有新增行；回读 | 整表历史回滚、悄悄把 <= 改成 >= |

这些评审验证模型输出的语义；仓库里的静态结构测试只验证规则没有丢失，不能替代行为评估。
